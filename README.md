# Бот «Свет ДТЭК»

Telegram-бот для нескольких человек, отвечает на украинском. Графики ДТЭК Киевские региональные электросети
он берёт из открытого репозитория [outage-data-ua](https://github.com/Baskerville42/outage-data-ua).

- Пользователь выбирает свою очередь кнопкой или пишет её номер, например `2.2`. Очередь можно узнать по адресу
  на [сайте ДТЭК](https://www.dtek-krem.com.ua/ua/shutdowns). У каждого свой список, до 10 очередей.
- Присылает график каждой очереди на сегодня и завтра картинкой и считает часы со светом и без него.
- Проверяет источник раз в 2 минуты и присылает график, если он изменился для очереди.
- Предупреждает за 15 минут до отключения, а если график резко изменился, сообщает сразу.

Команды: `/schedule` показывает графики, `/add` добавляет очередь, `/addresses` открывает список.

Адреса, добавленные раньше через поиск на сайте ДТЭК, продолжают работать, включая выбор линии для дома
на нескольких линиях. Но бот больше не сверяет их с сайтом, поэтому смену очереди нужно отслеживать самим.

## Датчик света через Xiaomi Home

Необязательная функция: бот сообщает о фактическом отключении и появлении света. Команда `/power` включает и выключает эти сообщения. Её нет в меню бота, потому что датчик показывает состояние одного дома.

Нужны устройство в обычной розетке и роутеры на ИБП, все в одном аккаунте Xiaomi Home.

| Шлюз | Роутеры | Что пишет бот |
| --- | --- | --- |
| Нет связи | На связи | «Схоже, світла немає», сколько свет был и что сказано в графике |
| Нет связи | Нет связи | Что нет связи с домом и о свете сказать нельзя |
| На связи | Любое | «Світло є» и сколько его не было |

Бот проверяет статус раз в 30 секунд и пишет при первом же изменении, поэтому о случайном обрыве шлюза он тоже сообщит. Чтобы такие обрывы отсеивать, задайте ожидание: `POWER_OFF_MINUTES` и `POWER_ON_MINUTES` в `.env`. Тогда сообщение придёт позже, но время в нём будет указано по первому обрыву.

Чтобы подключить датчик, выполните вход (в выводе будут и модели устройств), задайте `POWER_SENSOR_MODEL` и `POWER_REFERENCE_MODELS` в `.env` (образец в `.env.example`) и перезапустите бота:

```bash
node tools/xiaomi-watch.js
```

После входа в `data/xiaomi-session.json` хранится ключ к аккаунту Xiaomi. Публичного API для статуса устройств у Xiaomi нет, поэтому способ может перестать работать, а вход иногда придётся повторять. Бот сообщит об этом.

Нужен Node.js 22 или новее. Единственный сторонний пакет, `@resvg/resvg-js`, рисует картинку с графиком, поэтому перед первым запуском выполните установку:

```bash
npm ci
```

## Первый запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. Заполните файл `.env` (образец в `.env.example`): `BOT_TOKEN` и `ACCESS_CODE`.
3. Запустите бота:

   ```bash
   node --env-file=.env src/index.js
   ```

4. В консоли появится пригласительная ссылка. Откройте её сами и отправьте тем, кто будет пользоваться ботом.
   Без этой ссылки бот никого не пускает, поэтому не публикуйте её.

## Работа на сервере

Бот должен работать там, где не отключают свет: при отключении дома он перестанет получать изменения.

1. Скопируйте папку проекта на сервер (Ubuntu) без `.env` и `data/` и выполните в ней установку. Скрипт ставит Node.js и службу, но не запускает бота:

   ```bash
   sudo bash deploy/setup-server.sh
   ```

2. Остановите бота на старом месте. Telegram не отдаёт сообщения двум копиям с одним токеном.
3. Скопируйте `.env` в `/opt/dtek-svet-bot/` и `data/state.json` в `/opt/dtek-svet-bot/data/`, чтобы сохранить очереди. Назначьте им владельца `svetbot`, для `.env` поставьте права `600`.
4. Запустите службу:

   ```bash
   sudo systemctl start dtek-svet-bot
   ```

5. Посмотрите журнал. В нём не должно быть строк «Графики недоступны»:

   ```bash
   sudo journalctl -u dtek-svet-bot -f
   ```

## Бесплатный хостинг: Render + Neon

В этом режиме ноутбук после настройки не нужен. Render принимает сообщения Telegram через webhook,
а Neon постоянно хранит очереди пользователей и последний график в одной JSON-записи. История графиков не копится:
новое состояние заменяет предыдущее, а неизменившееся состояние повторно в базу не записывается.

1. Создайте бесплатный проект в Neon и скопируйте строку подключения `DATABASE_URL`.
2. Создайте в Render Web Service из этого репозитория. Файл `render.yaml` задаёт бесплатный тариф,
   `npm ci`, `npm start` и проверку `/healthz`.
3. В Render задайте секреты `BOT_TOKEN`, `ACCESS_CODE` и `DATABASE_URL`. Значения
   `WEBHOOK_SECRET` и `CRON_SECRET` Render создаст автоматически.
4. После успешного deploy скопируйте значение `CRON_SECRET`. В бесплатном HTTP-планировщике создайте
   запрос каждые 2 минуты:

   ```text
   POST https://ИМЯ-СЕРВИСА.onrender.com/tasks/tick
   Authorization: Bearer ЗНАЧЕНИЕ_CRON_SECRET
   Content-Type: application/json
   Body: {}
   ```

   Этот запрос запускает проверку графиков и предупреждений и не даёт бесплатному сервису Render уснуть.

Если в локальном `data/state.json` уже есть пользователи, добавьте `DATABASE_URL` в `.env` и один раз
загрузите состояние до запуска Render:

```bash
node --env-file=.env tools/upload-state.js
```

## Настройки

Необязательные параметры в `.env`:

| Параметр | По умолчанию | Что задаёт |
| --- | --- | --- |
| `POLL_SECONDS` | `120` | Как часто проверять источник графиков |
| `WARN_MINUTES` | `15` | За сколько минут предупреждать |
| `SCHEDULE_URL` | файл Киевской области в outage-data-ua | Откуда брать графики |
| `DATA_FILE` | `data/state.json` | Где хранить очереди пользователей и последний график |
| `DATABASE_URL` | — | Подключение Neon; включает режим webhook для хостинга |
| `WEBHOOK_SECRET` | — | Секрет проверки запросов Telegram |
| `CRON_SECRET` | — | Секрет планового endpoint `/tasks/tick` |

## Как это устроено

У ДТЭК нет открытого API, а сайт защищён от автоматических запросов и не пускает многие хостинги, в том числе Render.
Поэтому бот читает [outage-data-ua](https://github.com/Baskerville42/outage-data-ua): этот открытый проект
(лицензия MIT, без гарантий) раз в несколько минут переносит графики с сайта ДТЭК в JSON того же формата.
Адресов в нём нет, поэтому очередь выбирают сами.

- Изменения приходят примерно через 5–12 минут после сайта: источник обновляется раз в 5 минут, а GitHub кэширует файл.
- Кэш иногда возвращает более старую копию. Бот берёт данные, только если они новее уже полученных.
- Если источник не обновлялся больше 30 минут или сообщил об ошибке, бот считает его недоступным. Ещё через 30 минут
  он пишет об этом пользователям, а предупреждения продолжают идти по последнему графику.

- `src/schedule.js`: расчёт интервалов, часов и начала отключений.
- `src/source.js`: чтение графиков из outage-data-ua.
- `src/app.js`: диалог, уведомления и предупреждения.
- `src/index.js`: запуск и таймеры.
